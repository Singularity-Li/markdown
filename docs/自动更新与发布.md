# 维护者发布指南

普通贡献不需要发布权限或更新签名私钥。面向用户的安装与更新说明见 [README](../README.md)，开发流程见 [CONTRIBUTING](../CONTRIBUTING.md)。

## 发布前提

- 在默认分支，工作区干净，已审查并提交本次修改。
- GitHub CLI 已登录，拥有 `Singularity-Li/markdown` 写权限，网络可访问 GitHub。
- macOS 26+ / Apple Silicon 开发环境可运行测试与构建。
- 登录钥匙串包含原有 Ed25519 私钥（账户 `com.tony.markdown`），与 `Resources/UpdatePublicKey.txt` 匹配。不要自动生成替代密钥或公开私钥。

## 标准流程

```sh
# 自定义中文说明保存在被忽略的 dist/release-notes.md
python3 scripts/release.py --notes-file dist/release-notes.md

# 指定高于现有正式版的版本
python3 scripts/release.py --version X.Y.Z --notes-file dist/release-notes.md

# 仅准备，不发布
python3 scripts/release.py --prepare-only

# 恢复同一次未完成的发布
python3 scripts/release.py --resume vX.Y.Z
```

默认在最新正式版本上递增补丁号；`VERSION` 已提高时使用该版本。构建号必须高于此前交付版本。脚本完成历史与密钥检查、测试、根目录 App 构建、签名、压缩、提交推送、草稿上传校验、正式发布以及匿名下载和 latest 入口验证。

开发构建只在根目录组装 `Markdown.app`。发布可在 `dist/` 压缩该包，但不得生成第二份展开的应用。正式附件为 `Markdown-X.Y.Z.zip` 和已签名 `appcast.xml`。完整说明保存在 GitHub Release 与 `docs/releases/`。

## 失败恢复

失败时保留本地提交、草稿和 `dist/releases/vX.Y.Z/state.json`，排除故障后使用 `--resume`。若前置检查尚未写出状态文件，可重跑原命令。不得盲目递增版本、覆盖已发布附件、修改已签名清单或强推标签。只有脚本完成公开下载验证后才算发布成功。

## 客户端行为与边界

Sparkle 检查 GitHub 正式更新，下载、验签并安装；更新退出前仍需通过保存检查。支持恢复的版本会记录文件标签、模式和侧栏，重启后恢复一次，不恢复主动放弃的编辑。

对已批准的同一版本与地址，部分暂时安装错误最多重试三次，间隔 15、30、45 秒，可取消。取消、拒绝授权、签名错误、降级及网络下载错误不触发自动安装重试。主进程已退出后的错误不能由其继续重试。

当前为 ad-hoc 签名，不等于 Apple Developer ID 或公证。跨设备、企业安全软件及系统授权兼容性需实际验证。应用运行时由 Sparkle 在系统缓存暂存更新，与开发时的单一 App 产物规则不同。
