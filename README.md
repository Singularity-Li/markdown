# Markdown

适用于 macOS 26 及以上的原生 Markdown 阅读与编辑应用。

- 全窗透明背景，使用系统 Liquid Glass 与桌面背景模糊。
- 支持文件、文件夹、拖放、离线 Markdown 渲染及代码高亮。
- 支持同目录及子目录图片、标题锚点；网页链接在默认浏览器打开。
- 顶部标签页同时打开多份文档，支持文件多选和批量拖放；重复打开自动定位已有标签。
- 每个标签独立保留正文、预览/编辑模式和未保存状态；关闭标签或退出时提示保存，读写失败显示错误。

## 构建与验证

```sh
bash scripts/test.sh
bash scripts/build_app.sh
```

构建脚本直接在仓库根目录组装、签名并验证 `Markdown.app`，这是唯一 App 产出位置；不在 dist、临时目录、桌面等其他位置生成 App，也不创建测试或备份 App 副本。生成后可双击仓库中的应用运行。

快捷键：`⌘O` 打开文件或文件夹、`⌘S` 保存当前标签、`⌘W` 关闭当前标签、`⇧⌘P` 切换预览与编辑。

## 验证范围

回归检查覆盖多文件打开与去重、标签状态隔离、正确保存到对应文件、关闭与取消关闭、退出检查后台草稿、保存失败保护、目录导航及不支持格式占位。已实际验证多选打开、标签切换、保存和关闭、统一工具栏布局、页内格式提示，以及模式文字和颜色。

启动和直接打开文件时默认隐藏侧栏。通过统一打开入口或拖放打开文件夹时，侧栏自动展开；标题旁的侧栏按钮可随时收起或再次展开。

## 开发交付规范

每次完成开发，先验证并编译最新 App，再将源码与根目录 `Markdown.app` 一起提交、推送到远程。完整规范见 [AGENTS.md](AGENTS.md)。

开发完成后不再自动更新桌面的 App、示例文件或图片；仅在明确要求时操作桌面文件。构建缓存和备份不会纳入 Git。

每次交付同时维护 `.gitignore`：忽略缓存、日志、临时产物、截图、备份和个人环境文件，保留必要资源、开发文档及根目录 App。

多文件标签：点击顶部文件名切换，点击标签右侧 × 关闭。未保存标签显示圆点；标签较多时可横向滚动。打开目录保留已有标签，关闭全部标签后仍可从目录选择文件。

工具栏和标签栏横跨整个窗口，目录分隔线仅出现在下方内容区。不支持的文件以内容区占位提示展示，不弹出警告，且不会替换已有 Markdown 标签或修改原文件。

模式使用一体式“编辑 / 预览”分段控件，选中项分别以橙色或蓝色标识，每个标签保留自己的模式。

“打开”右侧的玻璃按钮可调节窗口背景透明度：点击显示滑杆，点击空白处收起。背景实时变化，正文与控件不随之淡化；设置自动保存并在重启后恢复。

中英文等页内切换链接保留文档自定义的 HTML 锚点（如 `id="zh"`、`id="en"`），自动生成的标题锚点会避开已用名称。`Markdown示例.md` 含可点击的中文 / English 双向跳转；回归检查使用 WebKit 验证实际渲染后的锚点。

新建与保存：通过工具栏新建图标或 ⌘N 新建，通过 ⌘S 或“文件 → 保存”保存。新文档以独立的“未命名”标签打开并自动进入编辑模式；首次保存选择名称和位置，后续直接保存到原文件。取消保存或保存失败时保留草稿，关闭有改动的文档时提示保存。

编辑模式提供实时 Markdown 源码高亮，涵盖标题、强调、删除线、列表、任务、引用、链接、图片、表格分隔符、代码、HTML，以及脚注和公式等扩展标记；保存内容仍为纯文本。扩展标记的高亮不代表预览支持对应扩展渲染。

应用图标使用苹果系统粗体的双色“MD”字母（深蓝 M、酒红 D），搭配 Liquid Glass 风格的半透明圆角底、柔和渐变、细亮边和轻阴影。字标占画布宽度 68%，玻璃底占 85%，四角透明，提供 16–1024 像素尺寸。ICNS 为静态玻璃质感，不提供实时背景模糊。

右上角操作按钮依次为新建、打开、透明度调整，均使用相同尺寸的纯图标按钮；悬停可查看功能提示。

顶部仅在标签页显示文件名，标签与操作按钮共用一行，减少正文上方留白。正文右下角实时显示当前文档非空白字符数（包含标点和 Markdown 标记），切换文档后同步更新。

顶部标签、图标按钮与模式控件统一为 28 点高，共用 36 点工具栏，并上移到标题栏区域；左侧预留窗口控制按钮空间。

右下角同时显示实时行数：按文本中的换行统计，包含末尾空行，不计自动折行；空文档显示 1 行。

新建文档、进入编辑模式或切回编辑标签时，焦点自动进入正文。预览正文随窗口宽度展开，左右仅保留 18 像素边距。

打开 Markdown 文件或切换文档后，键盘焦点自动进入正文区域；预览模式可直接用键盘阅读，后台预览加载和普通内容刷新不会抢走焦点。

图标更新：每次构建自动递增构建号，并按图标内容指纹命名资源。启动时直接从当前安装包加载 Dock 图标；首次运行、版本或图标变化、移动安装位置后更新当前 App 的 Launch Services 注册信息，失败则下次启动重试。此机制不修改已签名安装包，也不重启 Finder / Dock 或清空系统缓存。Finder 和未运行时的 Dock 图标仍由 macOS 管理，安装后建议启动新版一次；系统缓存刷新时间无法保证。

## 自动更新

App 启动后在后台检查 GitHub Releases 的正式版本；也可从 macOS 顶部菜单 **Markdown → 检查更新…** 手动检查。有新版时显示版本和更新说明，可安装、稍后提醒或跳过。点击安装后，Sparkle 自动下载、验签并重启；未保存文档仍会提示保存，取消则暂不退出。自动检查联网失败不打断编辑，手动检查会显示结果。

安装重试：在用户确认安装后，如果 App 仍在运行且安装助手启动、连接或写入等环节失败，将间隔 15、30、45 秒自动重试，最多 3 次。等待窗口支持取消；仅对已确认且版本号和下载地址均相同的更新自动继续。Sparkle 清理失败的安装包后，重试可能重新下载并验签。用户取消、拒绝授权、签名校验失败及降级等不自动重试。若 App 已被终止，无法由已退出的主进程执行重试；公司防护软件的实际行为仍需在对应设备验证。

下载与版本清单完全托管于 GitHub，无需独立网站或用户 Token。更新包与清单均经过 Ed25519 签名，支持 macOS 26+ / Apple Silicon。首次需要手动安装带更新功能的版本。当前 App 使用 ad-hoc 签名，更新签名不等同于 Apple Developer ID 签名或公证。

## 发布新版本

直接对本工程 Agent 说 **“发布新版本”**，或 **“发布 1.3.0，更新说明是……”**。Agent 会按 AGENTS.md 审查改动，完成测试、构建、签名、提交推送、草稿附件校验及正式 Release 发布。

```sh
# 默认递增补丁版本（首次使用 VERSION 中的版本）
python3 scripts/release.py
# 指定版本和更新说明
python3 scripts/release.py --version 1.3.0 --notes-file dist/release-notes.md
# 仅准备，或恢复同一次未完成的发布
python3 scripts/release.py --prepare-only
python3 scripts/release.py --resume v1.3.0
```

发布需要已登录且有仓库写权限的 GitHub CLI、可访问的 GitHub 网络及本机钥匙串中的更新签名密钥。脚本先验证草稿附件，再将 Release 设为 latest，最后匿名下载复验；网络失败可恢复，不覆盖已发布内容。普通提交不会触发更新。

构建版本由根目录 VERSION 管理。Sparkle 依赖固定为 2.10.0，Package.resolved 一同追踪。私钥保存在登录钥匙串（账户 `com.tony.markdown`），不得提交；换发布电脑须安全迁移原密钥。安装器运行时允许在用户缓存中暂存新包，但开发构建仍只生成根目录 Markdown.app。
